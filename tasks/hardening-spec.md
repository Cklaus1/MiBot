# MiBot — Hardening Spec (line-level bug/reliability pass)

> Generated by a 6-way parallel staff-engineer bug review (join, meeting, audio,
> transcribe+calendar, db+config, cli/orchestration), then hardened by **two
> independent adversarial prune passes** (A: join/meeting/audio · B:
> transcribe/calendar/db/cli). Every classification below was re-verified against
> source at HEAD. Recurring root causes are promoted to cross-cutting refactors
> **R1–R13** at the top. Ranked within each subsystem by severity (P0 → P3). Effort S/M/L.
>
> **Status:** VERIFIED (Phase 0 complete). Open questions resolved in Phase 2 (bottom).
> Safe to hand to the Phase 3 build harness.
>
> Severity bar: **P0** = crash/hang/silent data loss in *normal* operation ·
> **P1** = fails on common edge cases · **P2** = rare inputs · **P3** = polish.

## Prune changelog (what the two adversarial passes changed)

- **2 new P1s uncovered** (neither in the original 6-way pass):
  - **M15** — the Camofox/Meet monitor loop has **no** alone-timeout / grace /
    minHumans logic at all; a Meet call everyone left records silence up to
    `maxDurationHours`. Sibling of the M1 P0 on Meet's *primary* path.
  - **C19** — `joinAndRecord` (`bot.ts:50`) **always inserts a new meetings row**,
    even on the scheduled/watcher path that already has a `scheduled` row → duplicate
    rows + a **rejoin loop** (see finding). Must land **before** D6's UNIQUE index.
- **Severity corrections:** J6 P1→**P2**, J8 P2→**P1**, J17 P1→**P3**, D1 P1→**P2**,
  C13 P2→**P3**, CA9 P1→**needs-repro/P3**, M11 P2→needs-repro (kept P2, exposure noted),
  AU13 → confirmed *not a bug*, kept as P3 polish.
- **1 false positive removed:** C12 (camofox drop can't throw from `waitForTimeout` —
  it's a local `setTimeout`; the loop exits gracefully). Downgraded to a P3
  "wrap `updateHeartbeat`" note.
- **Cross-ref fixes:** CA3/CA4 tagged `→ D2` → should be **`→ D6`** (D2 is config
  validation, D6 is the dedup index); R7's subsumes-list said **CA9** → should be **CA7**.
- **Enum gap:** OQ3's status enum omitted **`no_audio`**, which the camofox path already
  writes (`bot.ts:108`) and transcribe's empty-file path needs. Resolved in OQ3.
- **Scope trims (over-engineering):** R12 cut to **fmtTime-only** (SQLite already parses
  every stored shape; no write-boundary migration); R13 **drops the "framed JSON
  protocol"** (one-shot request/response needs no framing); R10 config validation is a
  **~40-line hand-rolled coerce**, no schema library.

## Meeting lifecycle (meeting.ts, signals.ts)

### P0
- **M1** `meeting.ts:276` — `consecutiveEmptyPolls` freezes at 1: it increments only when `humanCount===0 && lastHumanCount>0`, but line 285 sets `lastHumanCount=0` after the first empty poll, so subsequent empty polls match neither branch and the counter never reaches the `>=2` gate. **Alone-timeout and grace-period exits can never fire** — when all humans leave, the bot stays until `maxDurationHours`. Fix: `if (humanCount===0) consecutiveEmptyPolls++; else consecutiveEmptyPolls=0;`. **→ empty-poll helper.** S. Test: polls `[2,0,0,0]` must exit via grace; currently never does. _(Prune A scope note: also covers the never-joined case where the bot sits in a waiting room and humanCount is 0 from the start.)_

### P1
- **M2** `meeting.ts:213` — unguarded `page.waitForTimeout(5000)`; if the page/browser closes mid-meeting it rejects "Target closed", escapes `waitForMeetingEnd`, and bot marks the meeting `failed` — valid recording + tracked participants/signals discarded. Fix: `.catch(()=>{})` + `page.isClosed()` break to run the normal finalize path. **→ R5.** S.
- **M3** `meeting.ts:35` — count-fallback fabricates `participant-0…N` human names from the aria-label count; these fail `isBot()` so count as humans (incl. the bot itself). Stale name selectors → `humanCount=1` forever, bot never leaves; ghosts persisted as real participants. Fix: return count separately, subtract self, never mint fake names. **P1.** M. **⚠ Sequencing (prune A): M1+M3 combined naively INVERTS M1** — a selector-churn `humanCount=0` would make the bot *leave an active meeting* (data loss). M3's fix must feed `aria-count-minus-self` into the leave gate, not raw scraped names. Land M1 and M3 as **one** change.
- **M4** `signals.ts:172` — chat dedup key `${sender}::${text}::${i}` uses DOM index; Teams virtualizes chat, so scrolling shifts every index and re-hashes the whole visible window as "new" → wholesale duplicate chat. Fix: key on stable content + per-(sender,text) occurrence counter. **→ R11.** M.
- **M5** `signals.ts:201` — hand-raise indicators re-scraped as a "reaction" every poll with no dedup (a 10-min hand = ~120 entries); real reactions spanning two polls double-count. Fix: drop hand-as-reaction (pollHandRaises covers it) + windowed dedup. **→ R11.** S.
- **M15** `bot.ts:403-580` (**NEW — prune A MISS #1**) — the **Camofox/Meet monitor loop has NO alone-detection at all**: it breaks only on `maxMs` (`maxDurationHours`) or the "Leave call" button disappearing. Test: camofox loop with People-count polls `[2,0,0,0]` must exit via grace.

## Sequencing constraints (must inform the build DAG)

1. **C19 → D6 → CA3/CA4.** The UNIQUE index can't land until `joinAndRecord` stops
   inserting duplicate `calendar_event_id` rows, and index creation needs a dedupe
   migration of existing rows or `CREATE UNIQUE INDEX` fails on live DBs.
2. **M1 + M3 land together.** Combined naively they invert M1 into leaving an active
   meeting (data loss); M3 must feed aria-count-minus-self into the leave gate.
3. **OQ3 enum (incl. `no_audio`) → R6 → T1/T2/C5/C7.** One status model, then all four.
4. **R1 → D3/D4/C6**, and R1's scope **must include the camofox path** (C5 adds a
   `processing` phase there that needs a heartbeat).
5. **R3 (awaited ffmpeg stop) + C13 (log flush) land with/before C1's signal exit** —
   the single graceful teardown path depends on both.
6. **M15 (Meet alone-detection) pairs with M1** — same failure mode, and both are
   subsumed if the architecture-spec's unified join/finalize pipeline lands.

## Open Questions → RESOLVED (Phase 2 canon)

- **OQ1 (R2/R3/R4 sequencing).** **Decision: one coordinated audio-lifecycle PR**, in
  the order R4 (hook source) → R3 (ffmpeg wrapper) → R2 (per-bot handles). They touch
  the same three files (audio.ts/recorder.ts/webrtc-capture.ts + bot.ts call sites);
  splitting them forces two rewrites of the same call sites. Effort L as one unit.
- **OQ2 (concurrency scope).** **Decision: in-process concurrency (`mibot start`,
  MAX_CONCURRENT_BOTS=3) is a supported mode — keep C4/AU9/J3/C8 at P1.** The watcher
  ships it today; serializing to one-process-per-meeting would be a larger architecture
  change than R2. R2 (per-bot sessions) is therefore required, not optional.
- **OQ3 (status enum).** **Decision — canonical recording-status enum:**
  `recording → recorded → {done | transcribe_failed}`, plus **`no_audio`** (capture
  produced nothing usable — camofox writes it today, transcribe's empty-file path maps
  to it) and **`failed`** (capture/pipeline error). No separate `degraded` — a truncated
  file is `recorded` with a logged warning. Meeting-status enum:
  `scheduled → joining → in_call → processing → {done | failed | missed}`. Adopt before
  R6/T1/C5/C7. Terminal recording statuses (`done`, `no_audio`, `transcribe_failed`,
  `recorded`) are never downgraded to `failed` by a post-processing catch (C7).
- **OQ4 (timestamp canon — R12 scope).** **Decision: fmtTime-only (cheap S).** Prune B
  proved SQLite's `datetime()` already parses every stored shape for scheduling, and
  D1's blast radius is display-only (offset datetimes). A write-boundary canonicalization
  + row migration buys nothing operational for a single-operator bot and adds migration
  risk. Fix `fmtTime` to handle offset/space/date-only; skip all-day events at ingest
  (CA8); drop the migration. **R12 is now S, not M.**
- **OQ5 (WebRTC tail-loss AU3 — recorder stop).** **Decision: single stop-and-drain at
  meeting end.** On finalize: stop the MediaRecorder, await the final `ondataavailable`,
  then drain both the periodic buffer and the tail in one two-phase read-then-ack
  (unifies AU3 + AU8 + AU12 into one drain protocol). Fold into the R4 audio PR.
- **OQ6 (option-injection T5 / config-crash D2 severity).** **Decision: T5 = P2**
  (single-operator, but display names come from meeting participants the operator
  doesn't control — the `--` separator is a one-line fix, cheap insurance). **D2 = P1**
  (config is user-edited and a bad value silently stops all joins — must validate).
  Playbooks/config are documented as user-editable, so both get validated at load (R10).
- **OQ7 (control-channel auth).** **Decision: out of scope for this hardening pass; log
  as an architecture item.** The socket is local-only; R13 sets it `0600` and hardens the
  edges. A local-process auth token is a separate security task — captured in
  `architecture-spec.md`, not built here.
- **OQ8 (dead code).** **Decision: "wire up if it closes a finding, else delete."**
  → `closeDb`: **wire** into the R13 signal path (closes D9). → `cleanupInfra`:
  **delete** + document pulse/Xvfb as host-persistent infra (AU14) — wiring it risks
  killing a shared daemon. → `extractAudio`: **delete** if truly unreferenced (confirm
  no call sites first). → `eval` control command: **remove from usage string** (C16) —
  don't implement (arbitrary-JS-over-socket is the OQ7 auth risk).
